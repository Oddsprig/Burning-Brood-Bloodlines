# Source audit through v0.094 and the recommended v0.095

Source: `main` at `2c7bd93d818810e005f7582f5687d38d1aeda5d2`, reviewed 6 November 2026. The owner requested Argon high for economy/towns/people, Grok 4.7 high for war/battles/dragons, and Sol 6.1 Max for houses/court/diplomacy/UI. The lead checked their source references and combined the findings below. The earlier Gemini draft was stopped and is not used here.

This was a source and documentation audit. **No game, editor, build or test was launched.** “Source defect” means a contradiction in the inspected code, with a described trigger; it is not a newly observed runtime failure. Frequency and native regression results remain unmeasured. All helper source snapshots were byte-verified unchanged: 117 economy, 117 war and 87 houses source files, with shared dependencies counted in more than one snapshot.

Source versions v0.086–v0.094 were already normally merged and pushed. The last packaged Desktop/Android release remains **v0.085**. This documentation commit creates no v0.095 build or new installation.

## Recommended v0.095

**Reliable campaign entry.** Fix the initial-design eligibility boundary so an offered history longer than one day can reach Begin, while retaining the selected historical day, real leader/household identity and one-time customization/focus. Resetting world history to day 1 would discard the very history the owner requested.

The evidence for the owner's intent is in the existing [history screen's recorded direction](../../game/ui/presim.gd#L2) and [original dynasty/city design](../handoff/original/HANDOFF_BURNING_BROOD.txt#L24), rather than a roadmap or an earlier assistant feature suggestion. Politics saved-location and truthful save completion are the next reliability repairs; include them only with an explicitly bounded acceptance plan. Keep the civic economy, battle settlement and marriage corrections visible as subsequent priorities.

The developer map did not already assign an authoritative next v0.095 milestone. Council roles and war demands are real unbuilt parts of the owner's design, but they rank below the entry and saved-progress defects. This is a recommendation, **not approval to build**. v0.095 remains unbuilt pending the owner's go-ahead.

## Review and acceptance boundaries

The lead rejected incorrect merge/source hashes, nonexistent catalog/class names and inaccurate documentation ages from the first economy draft. Its temple/reserve/records findings were rechecked against actual main source; population causality was downgraded to an unverified risk. Raw helper drafts and immutable inputs remain preserved in the director's `run086-095` working records. The integrated docs are the reviewed result, not a verbatim acceptance of each draft.

The war review confirmed the visible counter reader in `ui/victory.gd` and the actual weapon shading dependencies in `art/weapon_art.gd`/`art/pixel_canvas.gd`. A proposed union of all earlier fleeing units is not accepted as a fix: some may return in later engagements. Town, history-completion and weekly household integration dependencies omitted from individual snapshots were checked by the lead.

Historical acceptance remains as documented in [v0.086–v0.094 validation](../validation_v086-v094.md) and [v0.094 results](../economy_v094_results.md): 321 short controls, native day-53 mint and fresh-process reload through day 54. The owner stopped the 240-day run; its 165 accepted P10 days, day-173 census failure and earlier failures remain preserved. No full 240-day stability, old-save upgrade matrix, rendered performance or fresh package is claimed by this audit.

The standing three-document merge gate and post-merge light notes helper process are in [build rules](../BUILD_RULES.md), project memory and the shared machine testing/build rules. All three documents must contain the version's actual changes in the same version merge; otherwise do not merge.
